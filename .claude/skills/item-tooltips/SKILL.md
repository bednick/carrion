# Как называть механики в тултипе предмета

`stats()` — единственный источник правды по тексту, который видит игрок (R4, `docs/content.items.md`).
Внутри движка эффект может быть каналом (`channels()`), триггером (`triggers()`) или декларативным полем
(`weapon()`/`invuln()`/`emergencyHeal()`/`killHeal()`/`hitLeech()`) — см.
[`docs/combat-events.md`](../../../docs/combat-events.md).
**Игроку это не видно и видно быть не должно**: тир канала (`flat`/`increased`/`more`) — внутренняя
механика агрегации, в тексте никогда не упоминается. Игрок видит только *форму* эффекта — и вот для форм
нужен единый язык, иначе каждый новый предмет придумывает свою формулировку для уже описанной механики.

Числа в `stats()` обязаны читаться из **тех же констант**, что `channels()`/`weapon()`/`triggers()` —
не пересчитывать заново (R4). Этот скилл — про то, *как* эти числа подписывать, не про то, откуда их брать.

## Не пересказывай бриф

`stats()` — не место для формулировки, которой эффект описывался в промте или дизайн-заметке при
разработке предмета. Бриф может быть многословным и описательным; тултип — нет. Готовая строка обязана
ложиться в один из шаблонов таксономии ниже **дословно**. Если строка не ложится ни в один шаблон —
это симптом, что переписали пересказ вместо тултипа, а не то, что нашёлся особый случай.

## Таксономия форм

Семь форм, каждая — по наблюдаемому исходу для игрока, не по внутреннему механизму. Определи форму
**до** того, как писать строку.

### 1. Профильный стат (первичный)

Главная характеристика домена предмета — то единственное число, которое скейлится с редкостью (R5).
Пишется **без знака** (`+`/`−`), потому что это не модификатор чего-то чужого, а абсолютная величина
самого предмета.

```
Блок: 26%
Защита: 43%
Шипы: 20%
Урон: 8
```

Поясняющую фразу после значения (вроде «урона назад», «от максимума») пиши **только** если без неё число
неоднозначно — домен эффекта не тот, что подсказывает название канала (например, `%` считается не от
урона, а от макс. HP — так у форм 4/5). Если название канала уже однозначно называет физический смысл
(«Шипы» = контр-урон, «Блок» = шанс полного блока) — только `Label: N%`, без хвоста. Было
«Шипы: 20% урона назад» — избыточно, слово «Шипы» уже это говорит; правильно «Шипы: 20%».

Оружие — особый случай: пара «Урон» + «Перезарядка» идёт **всегда вместе**, в этом порядке, перезарядка —
в секундах с `.toFixed(1..2)` + `s` (не в процентах, не относительно чего-либо). Цвет у этой пары —
отдельный, не «Наступательное» (см. «Цвет строки» ниже): это единственные две цифры, по которым игрок
напрямую сравнивает разные виды оружия между собой, поэтому они выделены нейтральным белым, а не тонут
в общем оранжевом вместе с райдерами формы 2/7 (крит, пробитие, сплеш, доп. удары):

```
Урон: 8
Перезарядка: 1.46s
```

### 2. Риддер (вторичный стат того же предмета)

Второе число того же предмета, не самостоятельная ось, а надстройка над профильным статом (R5 разрешает
это как «слабый riderдер»). Тоже без знака, идёт **второй строкой** сразу после профильного стата.

**Один канал/триггер — всегда одна строка.** Не склеивай два числа через запятую, даже если оба риддера
относятся к одному домену эффекта — «относится к тому же домену» не значит «одна строка». У крита это
особенно легко перепутать: `crit_chance`, `crit_mult`, `crit_armor_pierce` — три независимых канала
боевого движка (см. `docs/combat-events.md` §«Консолидация крита»), а не один параметр с рider'ами друг
на друге. Правильный образец — `heavy_gloves`, где крит-шанс и крит-множитель идут раздельными строками.

```
Шанс крита: 20%
Множитель крита: ×3.5
Пробитие брони: 2
```

`war_pick` исторически писал «Множитель крита: ×3.5, пробитие брони: 2» одной строкой через запятую —
поправлено на три раздельные строки при написании этого правила, ориентируйся на актуальный код, не на
память о старых тултипах.

### 3. Добавка к чужому потоку (кросс-предметный/кросс-slot модификатор)

Число **не про сам предмет**, а про то, что он меняет в чужом канале (другое оружие, чужой крит-канал).
Всегда: (а) знак `+`/`−`, отражающий направление; (б) там, где канал привязан к конкретному предмету, а
не бьёт по общему потоку сразу — явно назван объект модификации (у крита это префикс «Доп.», крит-канал
и так один на бой, уточнять слот незачем).

```
Доп. крит-шанс: 15%
Скорость атаки: +10%
Скорость атаки: −30%
```

`weapon_interval_mult` — особый случай без объекта в тексте: канал не заскоуплен на один слот
(`scope` не задан), а действует на **каждый** надетый таймер оружия сразу (`docs/combat-events.md` §3,
`ChannelSet.query` — контрибуции без `scope` участвуют всегда). Раз объект — весь боевой поток атаки, а
не конкретное оружие в конкретном слоте, пиши голое `Скорость атаки: ±N%`, без «главного оружия» и без
имени слота.

`heavy_plate`/`light_gloves` исторически писали «Скорость атаки главного оружия», когда канал был жёстко
заскоуплен на `hand_right` (`scope: { targetSlot: 'hand_right' }`). Scope сняли, чтобы эффект бил по
любому надетому оружию, а не только по `hand_right` — уточнение «главного» стало неверным, поправлено на
голое «Скорость атаки». Ориентируйся на актуальный код (`src/items/light_gloves`, `src/items/heavy_plate`),
не на память о старых тултипах.

### 4. Условный эффект

Эффект применяется только при выполнении условия (HP-порог и т.п., R5 — порог фиксирован, не скейлится).
Формула: `<Что> при <условие>: <величина>`.

```
Защита при HP < 50%: 41%
Аварийный хил при HP < 20%: 20 HP (раз за забег)
```

### 5. Конечный ресурс (за бой / за забег)

Конечный запас, тратящийся по одному разу за срабатывание. **Скоуп обязателен в тексте**: игрок должен видеть,
восполняется запас каждым боем или выдан на весь забег — от этого зависит, беречь его или тратить. Единица —
«уд.» (заряды-удары) или явное «раз за …» в скобках после величины (не отдельной строкой).

```
Неуязвимость: 5 уд. за забег
Лечение за убийство: 5 HP (4 раза за забег)
Аварийный хил ...: 20 HP (раз за забег)
```

Все предметы слота `amulet` — ресурсы **за забег** (`content.items.amulet.md`). Форма «за бой» остаётся
законной для будущих механик на per-fight стейт-бэге; молча опускать скоуп нельзя ни в одном из случаев.

### 6. Вероятностный прок

Шанс на срабатывание эффекта (не гарантированный, в отличие от форм 1–5, где число — это либо
детерминированная величина, либо детерминированный шанс основного домена предмета типа блока). Формула:
`Шанс <события>: N% (+/− величина)`.

```
Шанс лечения за удар: 30% (+1 HP)
```

Отличие от «профильного стата» (форма 1): там шанс — это **сам домен** предмета (блок щита), здесь шанс —
условие срабатывания **побочного** эффекта (лечение — не домен амулета лайфстила как такового, домен —
«вероятность+исход»).

Если шанс **меняется по ходу забега** (затухание за каждый прок — `leech_bead`), это отдельная вторая строка
формы «Каждое срабатывание: шанс ×K до конца забега», цветом `PENALTY_COLOR` (это ухудшение, пусть и заложенное
в дизайн предмета). В первой строке остаётся стартовый шанс — не пересчитанный, без оговорок в скобках.

### 7. Форма атаки (третья строка оружия с `shape ≠ single`)

Оружие с нестандартной формой атаки (`cleave`/`pierce`/`multihit`/…) добавляет третью строку сразу после
«Урон» + «Перезарядка».

Если `shapeParams` хранит числовую величину, которую читает `weapon()` — строка **всегда**
`<Label>: <значение>`, число берётся из той же константы/поля, что передаётся в `shapeParams` (не
дублируется литералом прозы, R4):

```
Сплеш урон до 50%       (cleave, из shapeParams.splashRatios[0])
Ударов за атаку: 2      (multihit, из shapeParams.hits)
```

Если у формы нет числового параметра — сама форма фиксированное определение, не тюнится редкостью или
данными (`pierce` всегда бьёт ровно основную цель + одну позади) — короткое предложение без чисел и без
слов-заполнителей («также», «дополнительно», «в том числе»):

```
Наносит урон стоящему за целью противнику
```

`rapier` исторически хардкодил текстом «Наносит два удара за одну атаку» вместо чтения
`shapeParams.hits` — поправлено на «Ударов за атаку: 2», источник числа общий с `weapon()`.

Не изобретай синоним, если термин уже занят другим предметом с тем же каналом:

|--------------------------------------------------------------|-------------------------------------|------------------------------------------------------------------------------------------------------------------------------------|

| `block_chance`                                               | «Блок»                              | «Уклонение», «Отражение»                                                                                                           |
| `dodge_chance`                                               | «Уклонение»                         | —                                                                                                                                  |
| `crit_chance`/`crit_mult`                                    | «Шанс крита» / «Множитель крита»    | «Критический удар», «Крит-фактор»                                                                                                  |

| `weapon_first_tick_ratio`                                    | «Первый удар боя быстрее»           | «Инициатива», «Alacrity»                                                                                                           |

Держи этот словарь синхронным с `docs/content.items.md` §«Теги» — там те же понятия зафиксированы как теги
для дизайна/синергий (английские, `snake_case`), тут — их обязательный русский текст для игрока.

## Числа: округление и знак

- Проценты — всегда `Math.round(x * 100)`, никогда сырую дробь (`0.26` → `26`, не `0.26` и не `26.0`).
- Множители — `×N` (без пробела после `×`), не `xN`/`N times`.
- Секунды — `.toFixed(1)` или `.toFixed(2)` (смотри на существующие соседние оружия того же архетипа —
  `toFixed(2)` там, где интервал подгоняется под сотые доли ради точного DPS-анкора, иначе `.toFixed(1)`).
- Целочисленные величины (заряды, очки пробития) — без округления, просто число + короткая единица
  («уд.», «очк.» не пишем, просто число — см. «Пробитие брони: 2»).
- Знак `+`/`−` — **только** у формы 3 (добавка к чужому потоку) и у процентных «штрафов» (форма 3 в минус,
  напр. замедление). Формы 1, 2, 4, 5, 6 — без знака, это не дельта, а абсолютная величина.

## Цвет строки

Цвет — по **природе эффекта**, не по предмету и не по слоту. Все цвета живут в одном месте —
`src/items/statColors.ts` — это единственный источник правды для hex-значений. **Никогда не заводи цвет
как строковый литерал (`'#ffcc44'`) или локальную константу в `behavior.ts` предмета** — импортируй
именованную константу оттуда. Если нужна новая природа эффекта — сначала заведи для неё константу в
`statColors.ts` (с комментарием, какую природу она означает), синхронно добавь строку в таблицу ниже,
потом уже используй в предмете.

| Природа                                                   | Константа (`statColors.ts`) | Пример                                                   |
|-----------------------------------------------------------|-----------------------------|----------------------------------------------------------|
| Профильная пара оружия (`weapon().baseDamage`/`interval`) | `WEAPON_COLOR`              | Урон, Перезарядка                                        |
| Наступательное (райдеры формы 2/7, пробитие брони)        | `OFFENSE_COLOR`             | Ударов за атаку: N, Сплеш урон до N%, Пробитие брони     |
| Крит (`crit_chance`/`crit_mult`)                          | `CRIT_COLOR`                | Шанс крита, Множитель крита, Доп. крит-шанс              |
| Защитное (блок, защита)                                   | `DEFENSE_COLOR`             | Блок, Защита, Защита при HP < N%                         |
| Реактивное (шипы, контрудар)                              | `REACTIVE_COLOR`            | Шипы, Контрудар                                          |
| Лечение/лайфстил                                          | `HEAL_COLOR`                | Шанс лечения за удар, Лечение за убийство, Аварийный хил |
| Утилитарная добавка к чужому потоку (не штраф)            | `UTILITY_COLOR`             | Скорость атаки: +N%                                      |
| Штраф или затухание собственного эффекта (R7, `leech_bead`) | `PENALTY_COLOR`           | Скорость атаки: −N%; Каждое срабатывание: шанс ×K до конца забега |
| Конечный ресурс, счётчик зарядов (неуязвимость)           | `RESOURCE_COLOR`            | Неуязвимость: N уд. за забег                             |

«Урон»/«Перезарядка» выделены в `WEAPON_COLOR`, а не `OFFENSE_COLOR` — это единственная пара, по которой
игрок прямо сравнивает разные виды оружия между собой (DPS-анкор, `docs/content.items.hand_right.md`), и
она не должна тонуть в общем оранжевом вместе с райдерами форм 2/7 того же предмета (крит, пробитие,
сплеш, доп. удары), которые от оружия к оружию не совпадают по смыслу и для сравнения не годятся. Все
существующие оружия используют `WEAPON_COLOR` для этой пары: `broadaxe`/`rapier`/`short_spear`/`war_pick` —
импортируют напрямую в `stats()`; `battle_staff`/`dagger`/`short_sword` — через общую фабрику
`standardWeapon()` (`src/items/factories.ts`, тоже импортирует из `statColors.ts`), сами `stats()` не
задают — цвет уже приходит правильным, трогать его в самом предмете не нужно.

Крит выделен отдельной природой (не `OFFENSE_COLOR`), чтобы крит-ветку предмета было видно на глаз,
отдельно от базового урона. Один цвет на оба крит-канала — `crit_chance` и `crit_mult` читаются как одна
смысловая группа «крит», разбивать её на разные цвета незачем (см. `war_pick`, `heavy_gloves` — их
«Шанс крита»/«Множитель крита» переведены на `CRIT_COLOR` при заведении этого правила).
`crit_armor_pierce` в эту группу **не входит**: пробитие брони — про броню цели, не про сам крит-бросок
(домен «наступательное», хоть и триггерится только на крите как rider формы 2) — «Пробитие брони»
остаётся на `OFFENSE_COLOR`, как у `war_pick` в коде.

Если новый канал не ложится ни в одну строку таблицы — не изобретай десятую константу: подбери ближайшую
по духу природу (профильная пара оружия/наступление/крит/защита/реакция/лечение/утилита/штраф/ресурс) и
используй её.

## Порядок строк

1. Профильный стат (форма 1) — всегда первым. У оружия — «Урон» затем «Перезарядка», затем форма атаки
   (форма 7), если `shape ≠ single`, третьей строкой.
2. Риддер (форма 2), если есть.
3. Условный эффект (форма 4) или вероятностный прок (форма 6), если это и есть суть предмета (иначе они
   и есть форма 1 для этого конкретного предмета — см. `thread_charm`, у которого условный эффект **это**
   единственная строка).
4. Добавки к чужому потоку (форма 3) — последними, они про «что предмет даёт другим», не про себя.

## Чеклист для нового предмета

1. Определи канал(ы)/триггер(ы) — уже сделано, если следуешь `docs/combat-events.md` при добавлении эффекта.
2. Для каждого канала/триггера определи форму (1–7) по таблице выше. Несколько чисел одного домена (крит
   и т.п.) — это несколько раздельных строк, не одна через запятую (форма 2).
3. Возьми термин из «Словаря терминов» — если канала там нет, добавь строку в словарь **в этом файле**, не
   только в код (иначе следующий предмет с тем же каналом снова изобретёт синоним).
4. Собери строку по шаблону формы, знак — только для формы 3.
5. Проверь: число в `stats()` читается из той же константы/таблицы по редкости, что в `channels()`/
   `weapon()`/`triggers()` — не задублировано отдельным литералом.
6. Цвет — по природе эффекта из таблицы цветов, не «на глаз».
