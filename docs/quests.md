# Квесты

## Типы квестов

| Тип         | Источник                 | Описание                                                          |
|-------------|--------------------------|--------------------------------------------------------------------|
| Обучающие   | Автоматически            | Одноразовые, учат механикам, срабатывают по событиям               |
| Зональные   | По паре на область (9)   | `<zone>_clear` (убить босса) + `collect_<zone>_items` (собрать всё) — выдаются одновременно |
| Поле битвы  | Цепочка из 5             | `battlefield_survive_N` (продержаться N боёв за забег), N = 10/20/30/40/50 |

Золота в игре нет. У квестов два типа наград: `unlock_area` (разблокировать зону) и
`essence` (эссенция заданного тира и количества, см. таблицы ниже). Обучающие квесты наград не
дают, это чисто галочки прогресса.

## Засчёт через условие (`QuestCondition`)

Квест завершается, когда его условие (`src/quests/definitions.ts`) выполнено; `QuestSystem` сверяет
это автоматически:

- при изменении статов (`stats_changed`) — по ходу игры;
- при выдаче квеста (`quest_granted`) — **задним числом**: если игрок выполнил цель заранее, квест
  засчитывается сразу при появлении.

`QuestCondition` — дискриминированный union с тремя видами:

- **`{ kind: 'stat', stat, id?, count? }`** — засчитывается, когда `stats[stat][id] >= count` (или
  сумма по всем id, если `id` не задан). Используется у боевых квестов зон
  (`<zone>_clear` → `{ kind: 'stat', stat: 'zones_returned', id: '<zone_id>' }`).
  `zones_returned` растёт только при полном зачёте зоны (добит босс); ретрит не считается,
  поэтому условие эквивалентно «убить босса локации». Завязка на зону, а не на `mob_id`,
  устойчивее: некоторые боссы делят `mob_id` (напр. `beast-lair` и `predator-pasture` — оба `rat`).
- **`{ kind: 'zone_items', itemIds }`** — засчитывается, когда для **каждого** id из списка
  `stats.items_carried_out[id] > 0` (предмет хоть раз вынесен из экспедиции в сундук). Используется у
  квестов сбора (`collect_<zone>_items`); `target` квеста равен `itemIds.length`, так что прогресс в
  трекере/списке заданий честно показывает `N/M`. Список `itemIds` зашит прямо в `QuestDef`
  (совпадает с объединением `mob_loot.items` + `boss.loot.items` соответствующей зоны), а не
  вычисляется рантаймом — так надёжнее и не зависит от будущих правок конфигов зон.
- **`{ kind: 'battlefield_depth', depth }`** — засчитывается, когда лучший забег в endless-зоне
  (`meta.battlefield_best_depth`) дотянул до `depth`. Используется у цепочки Поля битвы
  (`battlefield_survive_N`); `target` квеста равен `depth`, так что прогресс в трекере честно
  показывает `N/M`. Считается **лучший забег**, а не сумма боёв за все заходы: «продержись 50 боёв»
  = дойти до 50-й глубины за один раз.

Обучающий квест `tutorial_equip` условия не имеет — засчитывается напрямую по событию `EventBus`
(`item_equipped`), обучающая цель разовая и не по id.

## Маркер на карте

У `QuestDef` есть поле `areas?: string[]` — список id зон (из `MAP_ZONE_LAYOUT` в `CampScene.ts`),
в которых можно выполнить квест. Пока не выполненный (активный) квест с непустым `areas` рисует
значок «?» в углу узла соответствующей зоны на карте. У квестов сбора `areas` дублирует зону из
`condition.itemIds` — то же значение, но это отдельное поле: `condition` двигает прогресс квеста,
`areas` только для отображения на карте.

## Обучающие квесты

Выдаются автоматически, последовательно. Не привязаны к NPC. Наград не дают (продажи в игре нет).

| ID                     | Триггер                       | Цель                         |
|------------------------|-------------------------------|-------------------------------|
| `tutorial_equip`       | Первый предмет попал в сундук | Надеть любой предмет          |

## Зональные квесты и квесты сбора

Пара квестов на каждую из 9 областей (у центра — Поля битвы — своя цепочка, см. ниже; сама зона
открывается по топологии, когда зачищены все 9). **`<zone>_clear` и `collect_<zone>_items` выдаются одновременно**,
как только зона открылась — не один после другого:

1. **`<zone>_clear`** («Исследовать: `<название зоны>`») — цель: победить босса локации
   (`condition: { kind: 'stat', stat: 'zones_returned', id: '<zone_id>' }`). Награда — эссенция
   (см. таблицу ниже).
2. **`collect_<zone>_items`** («Собрать: `<название зоны>`») — цель: вынести из экспедиции хотя бы по
   одному экземпляру каждого предмета этой зоны (`condition: { kind: 'zone_items', itemIds: [...] }`,
   `target` = число предметов). **Награда — `unlock_area` следующей зоны маршрута** (это и заменяет
   бывшую покупку проходки за золото) плюс эссенция.

Оба квеста зоны N+1 выдаёт `collect_<zone_N>_items` предыдущей зоны маршрута — его `next` содержит
сразу пару `[<zone_N+1>_clear, collect_<zone_N+1>_items]`. Первая зона маршрута 1 (`dead-fields`)
особая — обе её квеста сидятся сразу в стартовом состоянии меты (`MetaStore.createDefault`), без
какого-либо квеста-триггера. `next` самого `<zone>_clear` на «свой» `collect_<zone>_items` оставлен
как подстраховка для сохранений, начатых до этого изменения (addActiveQuest идемпотентна по id —
для новых партий это no-op, см. `src/quests/definitions.ts`).

Пока `collect_<zone>_items` не выполнен, следующая зона на карте показывает замок с прогрессом
сбора (`N/M`) вместо кнопки покупки — см. `CampScene.buildMapZoneNode`.

Особый случай — `dead_fields_clear`: помимо своей обычной награды-эссенции, он же (а не
`collect_dead_fields_items`) разблокирует старты 2-го и 3-го маршрутов — Растоптанные луга и
Свалку доспехов (`unlock_area` × 2 в `rewards`), и сразу выдаёт обе пары их квестов (`next`). Это
единственная точка входа во 2-й и 3-й маршруты, и она срабатывает уже на первом прохождении
Мёртвых полей, не дожидаясь сбора всех предметов зоны. `collect_dead_fields_items` в остальном
ведёт себя как обычный квест сбора — открывает только следующую пару квестов своего маршрута
(Руины магов).

Цепочки (по `FACTION_ROUTES`; `+` — пара квестов зоны выдана одновременно):

```
Маршрут 1: [dead_fields_clear + collect_dead_fields_items] → [mage_ruins_clear + collect_mage_ruins_items] → crypt_clear
Маршрут 2: [trampled_meadows_clear + collect_trampled_meadows_items] → [beast_lair_clear + collect_beast_lair_items] → predator_pasture_clear
Маршрут 3: [armor_dump_clear + collect_armor_dump_items] → [abandoned_camp_clear + collect_abandoned_camp_items] → marauder_lair_clear
```

Конечные зоны маршрутов (`crypt`, `predator-pasture`, `marauder-lair`) ведут к Полю битвы. У них нет
парного квеста сбора и `next` — гейт центра завязан на зачистку всех 9 зон (`completed_areas`), а не
на квест, и этим механизмом не затрагивается.

### Награда-эссенция по тирам зон

Награда растёт по мере продвижения по маршруту (3 тира по 3 зоны каждый); финальные зоны маршрутов
(`crypt`/`predator-pasture`/`marauder-lair`) квеста сбора не имеют, поэтому у них только награда за
`<zone>_clear`.

| Тир | Зоны                                              | `<zone>_clear`     | `collect_<zone>_items` |
|-----|----------------------------------------------------|---------------------|--------------------------|
| 1   | `dead-fields`, `trampled-meadows`, `armor-dump`     | 10 uncommon эссенции | 4 rare эссенции          |
| 2   | `mage-ruins`, `beast-lair`, `abandoned-camp`        | 10 rare эссенции     | 4 epic эссенции          |
| 3   | `crypt`, `predator-pasture`, `marauder-lair`        | 10 epic эссенции     | —                        |

## Квесты Поля битвы

Поле битвы — endless-зона без босса, без реворд-драфта и с пустым `mob_loot.items`: сама по себе она
не даёт ничего, кроме рекорда глубины. Цепочка `battlefield_survive_N` и есть награда за зону.

| ID                       | Цель                          | Награда                                    |
|--------------------------|-------------------------------|--------------------------------------------|
| `battlefield_survive_10` | Продержаться 10 боёв за забег | 50 uncommon + 50 rare + 50 epic эссенции   |
| `battlefield_survive_20` | Продержаться 20 боёв за забег | 50 uncommon + 50 rare + 50 epic эссенции   |
| `battlefield_survive_30` | Продержаться 30 боёв за забег | 50 uncommon + 50 rare + 50 epic эссенции   |
| `battlefield_survive_40` | Продержаться 40 боёв за забег | 50 uncommon + 50 rare + 50 epic эссенции   |
| `battlefield_survive_50` | Продержаться 50 боёв за забег | 50 uncommon + 50 rare + 50 epic эссенции   |

Каждый следующий квест выдаётся через `next` предыдущего — то есть после клика «Забрать» у Скупщика,
как и во всех остальных цепочках. `unlock_area` в наградах нет: открывать после Поля битвы нечего.

Первый квест цепочки — единственный, который не выдаётся ничьим `next` и не сидится в стартовой
мете. Гейт Поля битвы — не квест, а `completed_areas` трёх финальных зон маршрутов
(`MetaStore.isCenterUnlocked`), поэтому `battlefield_survive_10` выдаётся из
`QuestSystem.grantBattlefieldChain`: та вызывается в начале `evaluateQuests` (каждый заход в лагерь,
`stats_changed`, `quest_granted`) и выдаёт квест, как только центр открылся. `addActiveQuest`
идемпотентна по id, так что повторные вызовы — no-op.

Отдельного события на прогресс не нужно: забег в endless-зоне всегда кончается возвратом в лагерь, а
вход в лагерь пересверяет квесты. Рекорд `battlefield_best_depth` пишется **и при смерти, и при
отступлении** (`ExpeditionScene.onHeroDeath` / `retreatToCamp`) — иначе уход с 40-й глубины оставил бы
рекорд нетронутым и не двинул бы квест.

Задним числом цепочка отрабатывает бесплатно: у игрока с рекордом 50 первый квест закроется прямо при
выдаче, после «Забрать» выдастся следующий и тоже закроется сразу — пять кликов у Скупщика подряд.

## Схема прогрессии через квесты

```
Старт
 │
 ├─ [tutorial_*] — обучение механикам (параллельно с основным прогрессом)
 │
 └─ [dead_fields_clear + collect_dead_fields_items] → [mage_ruins_clear + collect_mage_ruins_items] → crypt_clear ┐
      │ (открывает сразу обе пары ↓)                                                                              ├─ зачистка всех 9 → Поле битвы
      ├─ [trampled_meadows_clear + collect_trampled_meadows_items] → [beast_lair_clear + collect_beast_lair_items] → predator_pasture_clear ┤
      │                                                                                                            │
      └─ [armor_dump_clear + collect_armor_dump_items] → [abandoned_camp_clear + collect_abandoned_camp_items] → marauder_lair_clear ─────┘
                                                                                                                   │
                          battlefield_survive_10 → _20 → _30 → _40 → _50  ←── выдаётся по факту открытия центра ────┘
```
