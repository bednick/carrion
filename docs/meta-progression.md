# Мета-прогрессия

Прогрессия строится без уровней и очков прокачки.
Игрок продвигается через открытие областей, накопление ресурсов, расширение рецептов и улучшение снаряжения.

---

## Ресурсы

Золота в игре нет — единственный ресурс мета-прогрессии — эссенция.

### Эссенция

Материал для обычного улучшения редкости снаряжения. Тиров три: `uncommon`, `rare`, `epic`. Обычного
(`common`) тира нет — обычная эссенция упразднена; легендарного тоже нет — эссенцией до legendary
не подняться, единственный путь туда — слияние (см. «Снаряжение»), которое эссенцию не тратит.

- **Источник**: только награда за зональные квесты. Разборки предметов на эссенцию в игре больше
  нет (была раньше — убрана вместе с кнопкой «Разобрать дубликаты» у кузнеца).
  - Квесты `<zone>_clear` и `collect_<zone>_items` дают фиксированную эссенцию, тир и количество
    растут по маршруту (см. таблицу в `docs/quests.md`).
- **Применение**: ингредиент обычного улучшения (1 предмет + эссенция → следующий тир) —
  единственная стоимость операции. Повышение до тира T стоит **10 эссенций тира T**. Слияние
  (3 предмета → 1) эссенцию не использует вовсе.

Оба ресурса **глобальные** — общие для всех персонажей.

## Прогрессия

### Карта областей

- Открытие новых зон — через цепочку из двух квестов на каждую область: `<zone>_clear` (победить босса)
  выдаёт `collect_<zone>_items` (вынести из экспедиции все предметы этой области хотя бы по разу); его
  награда — `unlock_area` следующей зоны маршрута. Никакой покупки за ресурс нет (см. `docs/quests.md`)
- **Центральная область** открывается автоматически, когда все девять зон попали в `completed_areas`
- Пройденные области помечаются отдельно (можно перепроходить за лутом)
- Центральная область (`battlefield`) — endless-зона (см. `docs/content.zones.format.md`): в `completed_areas`
  никогда не попадает (цель рекордная, не «прохождение»). Лучший результат — `battlefield_best_depth`
  (сколько мобов подряд убито за лучший забег), обновляется `MetaStore.recordBattlefieldDepth` и при смерти
  в зоне, и при ручном отступлении. Это же поле — условие цепочки квестов `battlefield_survive_N`
  (`condition: { kind: 'battlefield_depth', depth }`, см. `docs/quests.md`)

### Снаряжение

- Сундук накапливает всё снаряжение (лут похода лежит в рюкзаке и переезжает в сундук при выходе из похода)
- **Три стойки для брони** — сохранённые пресеты билдов; активная стойка (`active_stand`) запоминается и
  используется при входе на локацию, её можно сменить на стенде или прямо в бою
- Основной вектор прогрессии: редкость снаряжения растёт через улучшение (1 предмет + эссенция → следующий тир)
  или через **слияние** (3 предмета одной редкости → 1 следующей, без эссенции; `fuseItems` в `items/craft.ts`).
  Тип итогового предмета при слиянии — случайно один из трёх вложенных, поэтому 3 одинаковых предмета дают
  гарантированное улучшение именно этого предмета
- Стоимость улучшения = **10 эссенций целевого тира**, без какой-либо другой платы. Слияние эссенцию не тратит —
  его цена это сами 3 предмета
- Улучшением (1 предмет + эссенция) доступны тиры до **эпического**. **Легендарное** снаряжение через улучшение
  не получить — единственный способ его скрафтить — слить 3 эпических предмета одной редкости; либо найти
  (награда за квесты / боссов высоких зон)
- Продажи и разборки предметов нет — лишнее снаряжение либо уходит в слияние, либо остаётся в сундуке
- Обмен эссенции у кузнеца открывается по мере появления источника: строка «отдать 1 эссенцию тира T»
  заблокирована, пока в `completed_areas` нет ни одной зоны, чей босс даёт эссенцию T
  (`isEssenceExchangeUnlocked` в `items/craft.ts` + `essenceSourceZoneIds` в `zones/registry.ts`).
  То есть `редкая→необычная` — после первой синей зоны, `эпическая→редкая` — после первой фиолетовой

## Персистентность

Хранилище: `localStorage`, ключ `carrion.meta.v1`.

> **Версионирование схемы пока не поддерживается.** Проект играется только локально, поэтому миграции старых
> сохранений мы не пишем. Несовместимые изменения формата меты (переименование/удаление полей, смена структуры)
> **допустимы без бампа версии ключа** — единственное требование: в описании правки явно перечислить, что меняется,
> и попросить вручную сбросить прогресс (`MetaStore.resetAll()` или очистка `localStorage`-ключа). Версионирование
> ключа вернём, когда появятся внешние игроки.

Все структурные ключи меты — `snake_case`, как и в json-конфигах (`completed_areas`, `unlocked_areas`,
`armor_stands`, `pending_reward`).

```json
{
  "essence": { "uncommon": 0, "rare": 0, "epic": 0 },
  "completed_areas": [],
  "unlocked_areas": [
    "dead-fields"
  ],
  "chest": [],
  "battlefield_best_depth": 0,
  "armor_stands": [
    { "head": null, "body": null, "legs": null, "hand_left": null, "hand_right": null, "ring": null, "amulet": null },
    { "head": null, "body": null, "legs": null, "hand_left": null, "hand_right": null, "ring": null, "amulet": null },
    { "head": null, "body": null, "legs": null, "hand_left": null, "hand_right": null, "ring": null, "amulet": null }
  ],
  "active_stand": 0,
  "stats": {
    "mobs_encountered": [],
    "mobs_killed": {},
    "items_crafted": {},
    "items_carried_out": {},
    "items_discovered": [],
    "zones_entered": {},
    "zones_returned": {}
  },
  "quests": {
    "active": [],
    "pending_reward": [],
    "completed": []
  },
  "seen_npc_dialogs": [],
  "seen_mob_mechanics": [],
  "tutorial_completed": false
}
```

### Структура элементов

**Предмет в сундуке / на стойке:**

```json
{
  "item_id": "dagger",
  "rarity": "rare"
}
```

**Запись квеста:**

```json
{
  "id": "dead_fields_clear",
  "progress": 0,
  "target": 1
}
```

`target` — снимок цели на момент выдачи квеста, не источник правды: определение в `QUEST_DEFS`
могло смениться (в зону добавили предмет — цель сбора выросла). При каждой сверке (`QuestSystem`)
`target` подтягивается из определения, а `progress` условий `zone_items` и `battlefield_depth`
пересчитывается заново по стате, а не копится дельтой — иначе старые сейвы застревали бы на
устаревшем списке предметов.

### Статистика (`stats`)

Глобальная накопительная статистика игрока (общая для всех персонажей). Все ключи-словари — по id
(`mob_id` / `item_id` / `zone_id`); set-поля хранят только факт.

| Поле                | Тип                   | Что считает                                                        |
|---------------------|-----------------------|--------------------------------------------------------------------|
| `mobs_encountered`  | `string[]`            | встречал в бою (вкл. боссов и саммонов; ставится при появлении на поле) |
| `mobs_killed`       | `{ id: число }`       | убил (боссы и саммоны — тут же; смена фазы босса не считается)      |
| `items_crafted`     | `{ id: число }`       | улучшил редкость предмета у кузнеца (улучшение или слияние)         |
| `items_carried_out` | `{ id: число }`       | предмет попал в сундук из экспедиции (лут + награда-выбор за босса) |
| `items_discovered`  | `string[]`            | предмет выпал хоть раз с любого врага                              |
| `zones_entered`     | `{ zone_id: число }`  | заходов в зону (без учёта «Продолжить поиски» — это та же экспедиция) |
| `zones_returned`    | `{ zone_id: число }`  | выходов живым (победа над боссом зоны)                              |

Любая мутация статов шлёт `EventBus.emit('stats_changed')`. Часть квестов засчитывается по этим полям через
`QuestDef.condition` — в т.ч. задним числом при выдаче (`quest_granted`). См. `docs/quests.md`.

### Реплики НПС (`seen_npc_dialogs`)

`string[]` — id уже показанных одноразовых реплик НПС (`src/core/DialogSystem.ts`,
`src/dialogs/definitions.ts`; UI — `NpcDialogBox`, см. `docs/ui.md`). Каждый триггер сам решает, что
показать, и сам добавляет свой id сюда через `MetaStore.markDialogSeen`, чтобы не повторяться:

- `faction_hint_<undead|beasts|marauders>` — первая смерть игрока в зоне соответствующей фракции:
  реплика о её боевой идентичности, и второй репликой — либо стартовое контр-оружие дарится в
  сундук (если его нигде нет), либо, если оно уже есть (сундук/любая стойка), совет взять его на
  следующую вылазку (`checkFactionDeathDialogs`).
- `smith_unlock_rare` / `smith_unlock_epic` — первое открытие обмена эссенции у кузнеца для
  каждого тира выше базового отдельно (rare→uncommon / epic→rare; `checkSmithUnlockDialog`). Каждая
  реплика называет конкретный обмен — что отдаёшь, что получаешь, — иконкой эссенции и её именем,
  окрашенным в цвет редкости (`DialogSegment`, rich-режим `NpcDialogBox`, см. `docs/ui.md`).
- `fuse_unlock` — первое открытие слияния у кузнеца, после прохождения всех трёх стартовых зон
  (по одной от каждой фракции; `isFuseUnlocked` в `src/items/craft.ts`, `checkFuseUnlockDialog`).

Аддитивное поле — старые сейвы без него получают пустой массив (`init()`), сброс прогресса не нужен.
Старый общий id `smith_unlock` (до разделения по тирам) в уже существующих сейвах остаётся
неиспользуемым — безвредный мусор, не требует миграции.

### Пояснения механик мобов (`seen_mob_mechanics`)

`string[]` — id механик (`MechanicId` из `src/ui/mobMechanics/index.ts`: `evade`/`block`/`armor`/`thorns`/
`summon`/`phase`), пояснительное окно к которым игрок уже видел. При первой за сейв встрече с механикой бой
встаёт на паузу и всплывает модалка (`src/ui/MobMechanicModal.ts`, см. `docs/ui.md`); id пишется сюда через
`MetaStore.markMechanicSeen` **в момент закрытия окна**, а не открытия — иначе рестарт сцены с открытым окном
(F11) съел бы пояснение. Перечитать механику всегда можно кликом по её гнезду в правой колонке — это уже не
трогает ни мету, ни паузу.

Тип в TS — `string[]`, а не `MechanicId[]`: `src/core` не импортирует `src/ui` (та же причина, что у
`seen_npc_dialogs`).

Аддитивное поле — старые сейвы без него получают пустой массив (`init()`), т.е. игрок увидит пояснения при
следующей встрече с каждой механикой. Сброс прогресса не нужен.

### Обучающая зона (`tutorial_completed`)

`boolean` — пройдена ли обучающая зона (`training-camp`, вне карты/маршрутов — см.
`docs/zones/training-camp.md`). Пока `false`: `unlocked_areas` не содержит ни одной реальной зоны, карта лагеря
рисует только плитку «Тренировочный лагерь» (`CampScene.buildMapContent`), а «Мёртвые поля» и их стартовые квесты
не посажены. Становится `true` через `MetaStore.completeTutorial()`, вызываемый из
`ExpeditionScene.onExpeditionComplete()` сразу по возвращении из этой зоны; разблокировку «Мёртвых полей» и посадку
её квестов делает отдельно `QuestSystem.grantTutorialUnlock()` (идемпотентно, на каждый вход в лагерь).

**Миграция старых сейвов.** Поле добавлено вместе с обучающей зоной — у сейвов, созданных раньше, его нет в
сохранённом JSON. `MetaStore.init()` трактует отсутствие поля как `true` (`parsed.tutorial_completed ?? true`),
**не** `false`: такой сейв уже прошёл через старый прямой старт с «Мёртвыми полями», и его прогресс не должен
откатываться назад в обучение. Только по-настоящему новые сейвы (ключ `carrion.meta.v1` в `localStorage` вовсе
отсутствует) получают `false` через `createDefault()`.

### Что сохраняется при гибели vs при победе над боссом

Экспедиция идёт до боя с боссом или до гибели; досрочно выйти можно кнопкой «В лагерь» (зона тогда не
засчитывается). Рюкзак вываливается в сундук на любом из исходов, поэтому от исхода зависит только
награда-выбор за босса и фиксация прогресса зоны.

| Данные                  | Гибель             | Победа над боссом                     |
|-------------------------|--------------------|----------------------------------------|
| Эссенция / лут          | ✓ (рюкзак→сундук)  | ✓                                      |
| Сундук                  | ✓                  | ✓                                      |
| Стойки для брони        | ✓                  | ✓                                      |
| Награда-выбор за босса  | ✗ (не выдаётся)    | ✓ (draft 1 из N из `boss.loot`)        |
| Прогресс области        | ✗ (не засчитан)    | ✓ (зона в `completed_areas`)           |
| Области / квесты        | ✓                  | ✓                                      |

### Инициализация

При первом запуске (ключ отсутствует) — создаётся структура с нулями, тремя пустыми стойками для брони (в первой
— короткий меч `short_sword` `common`, дефолт `defaultStands()`), пустым `unlocked_areas` и пустым списком активных квестов.
`tutorial_completed: false` — единственная доступная активность до её смены — обучающая зона `training-camp`
(вне карты/маршрутов, см. `docs/zones/training-camp.md`).

Сразу после прохождения `training-camp` (`MetaStore.completeTutorial()`) `QuestSystem.grantTutorialUnlock()`
открывает `dead-fields` (зона магической фракции) в `unlocked_areas` и сразу сеет её стартовые квесты
(`dead_fields_clear` + `collect_dead_fields_items`) — до этого момента поведение то же, что раньше было в
`createDefault()`, просто отложено до конца обучения. Две другие стартовые зоны открываются наградой квеста
`collect_dead_fields_items`, как и раньше (см. `docs/quests.md`).
