# Событийная модель боя

Бой строится как два независимых слоя поверх общего реестра событий — фундамент для системы предметов
и синергий, см. [`content.items.md`](content.items.md):

- **Каналы («сколько»)** — именованные числовые аккумуляторы (крит, блок, броня, шипы, лайфстил, cross-slot
  модификаторы таймера оружия). Предмет не «делает» эффект, а декларирует типизированный вклад в канал;
  агрегация — один раз при сборке героя/моба, не на каждое событие.
- **Триггеры («когда»)** — декларативные правила «на событие [+ условие] → действие» для того, что не
  сводится к числовому каналу (сейчас — только контрудар `buckler`). Per-fight состояние живёт в общем
  стейт-бэге, не в точечных полях `HeroState`.

Резолюция урона идёт **именованными стадиями** (dodge → block → % митигация → округление → HP-гейты →
реактивная стадия), а не порядком слотов в экипировке — исход боя больше не зависит от того, в каком слоте
лежит предмет-источник.

> **Статус: реализовано.** Модель живёт в коде: `src/combat/events.ts` (реестр событий), `src/combat/channels.ts`
> (каналы/агрегация), `src/combat/triggers.ts` (триггеры/стейт-бэг), `src/combat/resolution.ts` (стадии
> авторинга атаки и резолюции урона), `src/combat/CombatEngine.ts` (часы стамины + оркестрация + применение
> терминалов), `src/items/behavior.ts` + `src/items/factories.ts` (декларации предметов,
> `standardWeapon`/`standardArmor`/`standardShield`). Этот документ — источник правды.

## 1. Принципы

1. **Событие — объект** с `type` и типизированной нагрузкой (реестр — §2, не изменился).
2. **Каналы — числа, не хуки.** Статический (или условный, но детерминированный от снимка боя) вклад
   предмета в именованный канал. Никакого кода, реагирующего на событие — просто число, которое читает
   стадия резолюции в нужный момент.
3. **Триггеры — чистые читатели.** Принимают уже резолвленное событие, ничего в нём не мутируют
   (нет `replace`), могут только `spawn`-ить новые события. Порядок триггеров друг относительно друга
   не влияет на числовой исход — каждый видит один и тот же `e`.
4. **Состояние меняет только движок.** Он резолвит стадии, применяет терминальные события к HP и реагирует
   отрисовкой/звуком. Каналы/триггеры не мутируют состояние напрямую.
5. **Герой и моб — один резолвер.** `resolveDefense`/`resolveIncomingDamage` (`resolution.ts`) принимают
   «чьи каналы» считать — герой (`armor_pct`, доля) или моб (`armor_flat`, очки, из `MobDefense`). Модели
   намеренно разные (см. §6), но код резолюции один.
6. **Стадии фиксированы, порядок слотов — нет.** dodge → block → % митигация → округление → HP-гейты →
   реактивная стадия — всегда в этом порядке, независимо от того, в каком слоте лежит предмет-источник
   канала.

## 2. Реестр типов событий

Не изменился по сравнению с предыдущей версией модели — закрытый discriminated union, `src/combat/events.ts`.

```ts
type Side =
    | { side: 'hero'; slot?: SlotType }
    | { side: 'enemy'; id: string; idx: number };

type Origin =
    | { from: 'engine' }
    | { from: 'character' }
    | { from: 'item'; slot: SlotType }
    | { from: 'enemy'; id: string };

interface EventMeta {
    origin: Origin;
    cause?: GameEvent;
}

type GameEvent = EventMeta & (
    | { type: 'fight_start'; enemies: string[] }
    | { type: 'fight_end'; outcome: 'win' }
    | { type: 'attack_ready'; source: Side; target: Side }
    | { type: 'attack'; source: Side; target: Side; amount: number; armorPierce?: number; splash?: boolean; crit?: boolean }
    | { type: 'damage'; source: Side; target: Side; amount: number; raw?: number; armorPierce?: number; splash?: boolean; thorns?: boolean; crit?: boolean }
    | { type: 'block'; source: Side; target: Side; prevented: number; thorns?: boolean }
    | { type: 'dodge'; source: Side; target: Side }
    | { type: 'counter'; source: Side; target: Side }
    | { type: 'heal'; source: Side; target: Side; amount: number }
    | { type: 'kill'; source: Side; target: Side }
    | { type: 'summon'; source: Side; spec: EnemySpec; position?: number }
    );
```

Семантика `raw`/`armorPierce`/`splash`/`thorns`/`crit` — без изменений, см. комментарии в `events.ts` и §5
ниже. `EventResult` с `replace` **убран** из публичного контракта — мутация числовых полей события больше
не то, что предметы делают по очереди; она живёт внутри стадий резолюции (`resolution.ts`), не наружу.

## 3. Каналы

Закрытый реестр `ChannelId` (`src/combat/channels.ts`), по аналогии с `EventType`:

`crit_chance`, `crit_mult`, `crit_armor_pierce`, `block_chance`, `dodge_chance`, `armor_pct` (герой),
`armor_flat` (моб), `thorns_flat` (герой и моб — разные `ChannelSet`, один и тот же `ChannelId`),
`lifesteal_on_hit_chance`, `lifesteal_on_hit_flat`, `lifesteal_on_kill_pct`, `weapon_interval_mult`, `weapon_first_tick_ratio`
(последние два — cross-slot. `weapon_first_tick_ratio` обязателен со `scope.targetSlot`.
`weapon_interval_mult` обычно без `scope` — тогда влияет на КАЖДЫЙ надетый weaponTimer, не только
`hand_right`; `scope.targetSlot` возможен, если нужно точечно задеть один слот).

### Тиры и формула

```
final = (base + Σflat) × (1 + Σincreased) × Π(more_i)
```

- **`flat`** — константа, прибавляется к базе. Большинство текущих предметов (шанс блока, шанс крита,
  ставка лайфстила) используют только этот тир — доли `0..1` напрямую, без домножения на 100.
- **`increased`** — доли (0.2 = +20%) складываются, сумма применяется один раз. Пока не используется ни
  одним предметом каталога — задел под будущие массовые аддитивные баффы.
- **`more`** — каждый источник независимый множитель, `Π(more_i)`. Броня героя (`armor_pct`) — канонический
  пример: каждый предмет контрибутит `1 - pct` (0.74 = «пропускает 74%»), несколько источников стакаются
  произведением — то же самое, что раньше давала цепочка последовательных вызовов `mitigateDamage`, но не
  зависит от порядка слотов.

Значение вклада может быть функцией `(view: CombatView) => number` — для условных вкладов (`desperate_plate`:
полная защита ниже HP-порога, нейтральный множитель `1` выше). Список контрибуций всё равно строится один раз
при сборке героя/моба; динамическим бывает только конкретное число, читаемое в момент резолюции.

`ChannelSet.query(id, view, targetSlot?)` — резолюция канала; `targetSlot` фильтрует cross-slot каналы по
`scope.targetSlot` (контрибуции без `scope` участвуют всегда). `ChannelSet.roll(id, rng, view, targetSlot?)`
— сахар для `rng() < query(...)`.

### Консолидация крита

Крит — **один** агрегированный канал, а не бросок каждого предмета отдельно. `war_pick` (свой крит) и
`heavy_gloves` (внешний бонус) оба лишь декларируют вклад в `crit_chance`/`crit_mult`; сам бросок — общая
стадия движка (§4), один раз на удар. `crit_armor_pierce` применяется к любому криту героя, а не только
к криту, рождённому конкретно `war_pick`, — прямое следствие консолидации.

## 4. Триггеры

`TriggerDef` (`src/combat/triggers.ts`) — `{ id, event, condition?, action, initState? }`. `action` может
только `spawn`-ить новые события, читая уже резолвленное `e` и снимок боя `ctx.view`; мутировать `e` нельзя.

```ts
interface TriggerDef<T extends EventType = EventType> {
  id: string;
  event: T;
  condition?: (e: EventOf<T>, ctx: TriggerContext) => boolean;
  action: (e: EventOf<T>, ctx: TriggerContext) => { spawn?: GameEvent[] };
  initState?: (rarity: Rarity) => Record<string, unknown>;
}
```

Большинство сегодняшних эффектов (блок, броня, крит, шипы, лайфстил-за-удар/убийство) выражаются через
каналы + фиксированные engine-owned стадии — им триггер не нужен. Триггеры — точка расширения для того,
что каналом не выразить: контрудар `buckler` (спавнит настоящую `attack`, читая чужой базовый урон
кросс-slot) — единственный предмет каталога, использующий `triggers()` на сегодня.

### Per-fight стейт-бэг

```ts
type TriggerStateBag = Partial<Record<SlotType, Record<string, unknown>>>;
```

Слот → `{ id триггера → приватное состояние }`. `buildTriggerState(equipment)` строит его один раз при
сборке героя (`CombatEngine.buildInitialHero`) — свежий на каждый бой, тот же контракт сброса, что раньше
был у точечных полей `invulnHits`/`emergencyHealUsed` в `HeroState`, но теперь общий для **любого** будущего
stateful-предмета: новый триггер с памятью объявляет `initState()`, не требует новой правки в движке и
нового места, которое надо не забыть сбросить.

Неуязвимость (`ItemBehavior.invuln`) и аварийный хил (`ItemBehavior.emergencyHeal`) — не сами триггеры (это
гейты внутри резолюции урона, не реакции на произвольное событие), но их **рантайм-состояние** (заряды,
флаг «использован») живёт в том же стейт-бэге под ключами `invuln`/`emergency_heal`, по тем же правилам
сброса. Декларация читается один раз при сборке — сама механика (гашение урона, разовый порог) нуждается в
мутируемом per-fight состоянии, которого у стейтлес каналов/триггеров нет, см. §7.

## 5. Стадии резолюции

### Авторинг атаки (`resolution.ts:authorAttack`)

```
attack_ready  ← движок (часы): поток стамины слота заполнился
   ↓
shape         ← форма оружия (данные предмета: single/multihit/cleave/pierce), таргетинг — engine-owned
   ↓
крит          ← ОДНА общая стадия для всех форм: один бросок crit_chance/удар, crit_mult/crit_armor_pierce
   ↓
attack(и)     ← по одному на каждый RawHit
```

`weapon.shape` — данные, не код: `single` (одна цель), `multihit` (N ударов по той же цели, напр. `rapier`),
`cleave` (основная цель + сплеш по дальности, ступени фиксированы — `broadaxe`), `pierce` (основная цель +
живой враг в соседней ячейке позади — `short_spear`). Таргетинг cleave/pierce — engine-owned функции в
`resolution.ts` (перенесены из старых per-item хуков), новое cleave/pierce-оружие получает их бесплатно,
объявив только `shape`+`shapeParams`.

### Резолюция входящего урона (`resolution.ts:resolveDefense` + `CombatEngine.handleDamage`)

```
dodge → block → % митигация → округление (stochasticRound) → HP-гейты → применение к HP → реактивная стадия
```

Один путь для героя и моба — `resolveDefense` принимает `defenderChannels`+`isHero` и считает митигацию
по нужной модели (герой: `armor_pct`, доля-множитель, `more`-тир; моб: `armor_flat`, вычет очков,
`mitigateFlat` — модели намеренно разные, см. `docs/mechanics.md` §«Броня vs щит»). `dodge`/`block` —
полные короткие замыкания (см. таблицу §6); всё остальное — числа, независимые от того, в каком слоте
лежит предмет-источник канала.

**HP-гейты** (только герой): неуязвимость (`consumeInvuln`) проверяется после округления, до вычитания
из HP — полностью гасит удар, тратит один заряд из стейт-бэга. Аварийный хил (`applyEmergencyHealIfNeeded`)
— после вычитания, если HP/maxHp ниже порога и хил ещё не использован в этом бою.

**Реактивная стадия** (`CombatEngine.runReactiveStage`) — после HP-гейтов, независимо от того, был ли удар
заблокирован (шипы всё равно реагируют на факт удара) или дошёл ли до цели (лайфстил-за-удар гейтится на
`dealt > 0`, шипы — нет): шипы (канал `thorns_flat`, фикс. число за удар — и у героя, и у моба), лайфстил-за-удар
(`lifesteal_on_hit_*`), кастомные триггеры экипировки (`runTriggers`). Дюдж гасит вообще всё, включая эту стадию.

## 6. Как выражаются текущие эффекты

| Эффект                        | Канал/стадия                                                            |
|--------------------------------|---------------------------------------------------------------------------|
| Броня героя                   | канал `armor_pct`, тир `more` — стадия % митигации                        |
| Щит (блок)                    | канал `block_chance`, тир `flat` — стадия block (короткое замыкание)      |
| Крит (любой источник)         | каналы `crit_chance`/`crit_mult`/`crit_armor_pierce` — стадия крита в authorAttack, один бросок на удар |
| Лечение за убийство           | канал `lifesteal_on_kill_pct` — читается движком при обработке kill       |
| Лайфстил за удар              | каналы `lifesteal_on_hit_chance`/`_flat` — реактивная стадия, кроме `splash: true` |
| Контрудар (`buckler`)         | `TriggerDef` на `damage`(target=hero): `spawn:[attack(source.slot=hand_right)+counter]`, независим от исхода блока |
| Шипы (герой)                  | канал `thorns_flat` — реактивная стадия, фикс. число за удар, не зависит от исхода block/hit |
| Шипы (моб)                    | канал `thorns_flat` — та же реактивная стадия, полностью симметрично      |
| Броня моба                    | канал `armor_flat`, вычет очков (`mitigateFlat`) — стадия % митигации     |
| Уклонение моба                | канал `dodge_chance` — стадия dodge (короткое замыкание)                  |
| Блок моба                     | канал `block_chance`, тир `flat` — стадия block (короткое замыкание), тот же канал, что у щита героя |
| Cross-slot таймер оружия      | каналы `weapon_interval_mult`/`weapon_first_tick_ratio`, `scope.targetSlot` — читаются при постройке `weaponTimers` |

Старый «второй хук `on.block`» у `spiked_cuirass` (ловил блок чужого слота, случившийся раньше по
порядку слотов) **убран за ненадобностью** — шипы теперь одна engine-owned стадия, читающая `raw`, не
зависящая от того, какой слот резолвится первым.

## 7. Неуязвимость и аварийный хил — не хуки и не триггеры на произвольном событии

`amulet` может дать герою неуязвимость (N ударов без урона на бой) и аварийный хил (разово при HP ниже
порога) — см. [`content.items.amulet.md`](content.items.amulet.md). Это гейты **внутри** резолюции урона
(`CombatEngine.handleDamage`/`applyEmergencyHealIfNeeded`), не общие триггеры на событии — их точка
срабатывания жёстко привязана к конкретному месту в пайплайне (после округления / после вычитания HP), а не
к типу события в реестре.

- **Грант** читается один раз из `ItemBehavior.invuln`/`emergencyHeal` при сборке героя
  (`buildTriggerState`, тем же приёмом, что `weapon()` → `buildWeaponTimers`).
- **Рантайм-состояние** (заряды, флаг «использован») живёт в общем per-fight стейт-бэге под ключами
  `invuln`/`emergency_heal` (см. §4) — свежее на каждый бой, `hp`/`damageTakenMult` переносит вызывающая
  сторона (`ExpeditionScene`/`simulate.ts`) между боями одной экспедиции.
- Хот-свап экипировки среди боя (`ExpeditionScene.applyEquipToHero`) переносит остаток зарядов (клампится к
  новому максимуму) вместо сброса в максимум нового предмета — generic-перенос по форме стейта
  (`{charges, max}`), работает для любого будущего триггера с зарядами, не только `invuln`.

## 8. Округление, `raw`, `thorns`, `splash`, `crit`

Без изменений по сути (перенесено из старой модели, актуально для новой):

- `amount` в цепочке `damage` — дробный до самого конца; единственное округление — `stochasticRound` в
  `CombatEngine.handleDamage` (`E[x]=x`, поэтому процент брони работает одинаково на ударе любого размера).
- Пола в 1 урон нет: полностью погашенный небазовый удар — `block`, но rider-урон (`thorns`/`splash`),
  округлившись в 0, гаснет молча (без флоатера «Блок» на каждый мелкий тик).
- `raw` — урон до любых снижений, проставляется один раз при рождении `damage` из `attack`, нужен процентным
  шипам, чтобы доля считалась от исходного удара, а не от уже сниженного чужой бронёй.
- `thorns`-флаг — анти-цикл: урон, рождённый самими шипами, не реотражается ни героем, ни мобом, иначе шипы
  обеих сторон отражают друг друга по кругу (гасится `MAX_CASCADE`).
- `splash` — вторичные тики cleave (`broadaxe`); реактивная стадия лайфстила-за-удар их игнорирует, чтобы
  один взмах по толпе не лечил героя за каждую задетую цель.
- `crit` — презентационная метка (HP-математика уже применена стадией крита), нужна только для флоатера.

## 9. Пример сквозного прохода

Враг бьёт героя на 5. Надето: `spiked_shield` (`hand_left`, блок 21% + шипы 20%) + `barrier_amulet`
(`amulet`, 2 заряда неуязвимости).

```
dispatch(attack{src:enemy#1, tgt:hero, amount:5})
  → apply('attack') → damage{amount:5, raw:5}

handleDamage(damage):
  defenderChannels = hero.channels
  resolveDefense(5, undefined, heroChannels, isHero=true, view, rng)
    dodge_chance(hero) = 0 → нет
    block_chance(hero) = 0.21 → допустим, ролл не прошёл
    armor_pct(hero) = 1 (брони нет) → amount = 5
  outcome = { kind: 'resolved', amount: 5 }

  scaled = 5 (damageTakenMult=1)
  dmg = stochasticRound(5) = 5
  consumeInvuln() → заряд есть → тратим, onInvulnHit(), dmg не вычитается из HP

  реактивная стадия (runReactiveStage, raw=5, !e.thorns):
    thorns_flat(hero) = 1 → spawn: damage{src:hero, tgt:enemy#1, amount:1, thorns:true}
    (лайфстил-за-удар/триггеры — target.side='hero', не применимо для исходящего лайфстила)

queue: [ damage{src:hero, tgt:enemy#1, amount:1, thorns:true} ]

handleDamage(thorns-damage):
  defenderChannels = enemy#1.channels (armor_flat/dodge_chance из MobDefense, если заданы)
  ... резолвится тем же путём, обычный урон по мобу ...

queue пуст → стоп
```

Блок в этом примере не сработал (сработай он — `outcome.kind==='blocked'`, HP-гейты и вычитание HP
пропускаются, но реактивная стадия всё равно отрабатывает: шипы отражаются от `raw` независимо от исхода
блока).

## 10. Заметки

- **Порядок больше не имеет значения для числового исхода.** Каналы агрегируются суммой/произведением
  (коммутативны), стадии резолюции фиксированы кодом, а не порядком слотов экипировки. Единственное, что
  всё ещё зависит от порядка — порядок элементов в `hero.weaponTimers[]` (чисто косметически, для UI).
- **RNG.** Каналы/триггеры получают `rng` через контекст (`ctx.rng`/параметр `roll()`), не глобальный
  `Math.random` — для воспроизводимости через сиженный `Rng` (`src/core/rng.ts`), где это важно (фазовые
  переходы боссов; сам бой не сижен, см. `CombatEngine.dispatch`).
- **Несколько врагов и доска.** Без изменений — 4 фиксированные ячейки, позиция врага — `slot`, не индекс
  массива; `summon` садится в ближайшую свободную ячейку или гасится, если ячеек нет (лимит доски). См.
  [`content.mobs.format.md`](content.mobs.format.md).
- **Мобы могут получить триггеры без нового рефакторинга.** `EnemyState.triggerState` заведён (пустой у всех
  текущих мобов — ни один не декларирует триггеров), `MobConfig.defense` уже течёт в тот же резолвер, что и
  экипировка героя. Первая способность моба сложнее плоского `armor`/`dodge`/`thorns` потребует небольшого
  `src/mobs/<id>/behavior.ts` (по аналогии с `src/items/*/behavior.ts`), не изменения диспетчера.
