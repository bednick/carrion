# Контент: восстановление (слот `amulet`)

Источник правды по слоту `amulet`: домен, ось, характеристики предмета, список предметов и (для неуязвимости/
аварийного хила) движковый механизм, на котором они держатся. Общие правила системы предметов (R1–R9) и
функциональность слотов — [`content.items.md`](content.items.md); боевая идентичность фракций —
[`factions.md`](factions.md); событийная модель — [`combat-events.md`](combat-events.md).

## Домен слота

**Восстановление HP-ресурса героя.** Раньше домен планировался на `body` — решение пересмотрено: весь хил переехал
в `amulet` целиком, `body` отвечает только за снижение получаемого урона
([`content.items.body.md`](content.items.body.md)). Граница между слотами держится жёстко: `amulet` не снижает
входящий урон численно (это `body`/`hand_left`) — он либо возвращает HP, либо даёт герою неуязвимость от урона
на несколько ударов.

## Ось слота и решения этой правки

Два легаси-предмета уже в коде — `leech_bead` (лечение % от нанесённого урона, on_hit) и `vulture_amulet`
(лечение за килл) — оба на **наступательном** триггере (реагируют на урон, который наносит герой). Эта правка
закрывает наступательный триггер для **нового** контента: новых предметов, влияющих на исходящий урон, слот
больше не получает. `leech_bead`/`vulture_amulet` остаются как есть и подлежат обычному балансу чисел наравне с
остальными — не удаляются и не переосмысливаются.

Новые направления — только **защитные**, и только **косвенно**: реагируют на то, что происходит с героем, но не
через добавление стата снижения урона (это была бы прямая защита, домен `body`), а через HP-ресурс:

- **Аварийный хил** — реактивный, по состоянию героя (HP ниже порога), не более раза за бой.
- **Неуязвимость** — проактивная, по времени (открытие боя), N ударов полностью без урона.

Единой continuum-оси между этими двумя и легаси-парой в этой правке не вводится: три разных механических формы
(offensive-trigger лечение, threshold-triggered лечение, fight-start ресурс) описаны как открытый список, не как
жёсткий полюс-полюс (так же решили для `body`).

| Предмет                                      | Триггер                 | Профильный стат       | Природа                                    |
|----------------------------------------------|-------------------------|-----------------------|--------------------------------------------|
| Пиявочная бусина (`leech_bead`, легаси)      | урон, нанесённый героем | % лечения от урона    | наступательный, закрыт для нового контента |
| Амулет грифа (`vulture_amulet`, легаси) | килл                    | % макс. HP убитого врага | наступательный, закрыт для нового контента |
| Оберег на волоске (`thread_charm`, новый)    | HP героя < порога       | величина хила         | защитный, реактивный, 1 раз за бой         |
| Амулет барьера (`barrier_amulet`, новый)     | начало боя              | число неуязвимых ударов | защитный, проактивный, N ударов          |

## Отклонённые направления

- **Лечение за блок** — рассмотрено (был готовый пример в `combat-events.md` §7), отклонено: не берём.
- **Лечение за полученный урон** (безусловное) — отклонено: по эффекту неотличимо от брони (снижает эффективный
  урон на ту же величину через другой канал), дублирует домен `body`, а не дополняет его.
- **Пассивный реген по времени** (тик, не привязан ни к одному событию) — не берём в этой итерации: в движке нет
  тикающего вне таймера оружия триггера, событийная модель полностью event-driven. Кандидат на будущее.
- **Наступательный триггер для новых предметов** — закрыт этой правкой (см. выше). Существующие
  `leech_bead`/`vulture_amulet` — легаси-исключение, не прецедент для новых предметов.

## Неуязвимость — механика (проработана как основание для будущих предметов)

Не item-хук, а **движковый примитив уровня HP**: неуязвимость — новое поле состояния героя
(`HeroState.invulnHits`/`invulnHitsMax`), а не что-то, что предмет считает сам на каждое событие. Причина: ей
нужно **мутируемое состояние, которое живёт весь бой** (счётчик оставшихся зарядов) — у обычных item-хуков
такого нет, они честные `(event, ctx) => result` без памяти между вызовами. Тот же принцип уже применялся к
`hero.hp` — неуязвимость устроена симметрично.

- **Грант.** `ItemBehavior.invulnHitsGrant?: (rarity) => number` — декларативное значение, читается один раз при
  сборке героя (`CombatEngine.buildInitialHero`, функция `buildHeroResources`, тот же приём, что и у
  `attackInterval`/`buildWeaponTimers`). Суммируется по всей надетой экипировке (на практике — один амулет), не
  жёстко привязано к слоту `amulet`.
- **Выдача.** Полный `invulnHitsMax` — на **каждый** бой (`beginFight()` в `ExpeditionScene` строит нового героя
  через `buildInitialHero` при входе в следующий бой зоны). В отличие от HP (который явно переносится между
  боями забега — «накопительный сток», см. `roadmap.balance.md`), заряды **не переносятся**: каждый новый бой
  начинается с полного гранта, независимо от того, сколько осталось от предыдущего.
- **Срабатывание.** Место — `CombatEngine.applyDamage`, ветка `target === 'hero'`, **до** вычитания из
  `hero.hp`: если `hero.invulnHits > 0`, заряд тратится (`hero.invulnHits--`) и весь урон этого удара обнуляется
  (`dmg = 0`) — независимо от его величины, никакого частичного поглощения. Порядок в пайплайне: проверка стоит
  **последней** — `applyDamage` вызывается уже после полного прохода `runPass` (щит/броня/шипы уже отработали
  как item-хуки), поэтому неуязвимость гасит **финальный** урон после всей обычной митигации, а не сырой удар.
- **UI.** Новый колбэк `CombatCallbacks.onInvulnHit?()`, презентационный (не трогает `damage`-путь) —
  всплывающий текст «Неуязвимость!» (новый `FloaterType: 'invuln'`) + полупрозрачный сине-голубой оверлей
  поверх HP-бара (`ExpeditionScene.heroInvulnOverlay`) и счётчик оставшихся ударов слева от бара
  (`heroInvulnText`), видны только пока `invulnHits > 0`.
- **Расширяемость («мы будем добавлять новые механики поверх него»).** Неуязвимость — состояние движка, не
  спрятанное в замыкании одного предмета, поэтому будущие эффекты могут читать текущее число зарядов
  (`CombatView.heroInvulnHits`/`heroInvulnHitsMax` — стоит завести по аналогии с `heroHp`/`heroMaxHp`, если/когда
  появится первый потребитель) или гранить заряды из другого источника (килл, реакция на низкий HP и т.п.) —
  сам счётчик уже общий ресурс, не собственность одного предмета.

### Открытые вопросы неуязвимости

1. **Хот-свап экипировки посреди боя** (`ExpeditionScene.applyEquipToHero`) пересобирает героя целиком
   (`buildInitialHero`) и явно переносит `hp`, но **не** переносит `invulnHits` — значит, смена амулета посреди
   боя полностью обнуляет/переполняет заряды до нового максимума. Для HP это осознанно иначе (перенос), для
   неуязвимости пока не решали отдельно — вероятно, ту же логику переноса стоит применить (`fresh.invulnHits =
   Math.min(engine.state.hero.invulnHits, fresh.invulnHitsMax)`), но это отдельное микрорешение, не блокирующее
   первую итерацию.
2. **`CombatView` пока не содержит `heroInvulnHits`** — добавить, когда появится первый предмет/эффект, которому
   нужно читать текущий счётчик (YAGNI: не заводить прежде первого потребителя).

## Аварийный хил — механика

Тоже движковый примитив, не item-хук — по той же причине: нужен флаг «уже сработал в этом бою»
(`HeroState.emergencyHealUsed`), мутируемый между несколькими проходами `damage`.

- **Конфиг.** `ItemBehavior.emergencyHeal?: (rarity) => { thresholdRatio, healPercent }` — декларативно, читается
  один раз в `buildInitialHero` (та же `buildHeroResources`). `thresholdRatio` **не скейлится редкостью**
  (фиксирован на 30%, R5 — один профильный стат на архетип, им выступает `healPercent`). `healPercent` — доля
  от `heroMaxHp` (0..1), не флэт-число: сам хил считается от `hero.maxHp` **в момент срабатывания**
  (`applyDamage`), а не один раз при сборке героя — если maxHp когда-нибудь станет зависеть от экипировки/статов,
  хил останется корректным без правки этой механики.
- **Срабатывание.** `CombatEngine.applyDamage`, после того как урон (уже прошедший через проверку неуязвимости)
  вычтен из `hero.hp`:
  если герой жив, эффект ещё не использован в этом бою и `hp / maxHp < thresholdRatio` — лечит на
  `round(maxHp * healPercent)` (капается по `maxHp`, как обычный `heal`) и ставит `emergencyHealUsed = true`.
  Флаг сбрасывается каждый новый бой (`buildInitialHero`), не при смене фазы одного боя (воскрешение Нежити не
  даёт второй заряд в той же битве).
- **Почему «раз за бой», а не пороговый без лимита.** Без ограничения эффект стабильно доливал бы HP на
  **каждом** ударе, пока герой ниже порога — фактически становясь ещё одной формой мягкой брони, только выраженной
  через хил, и переставая быть «аварийным». Лимит держит его редким и заметным, как и задумано.
- **UI.** Переиспользует существующий `onHeal`-канал (тот же флоатер/обновление HP-бара, что у `leech_bead`/
  `vulture_amulet`) — отдельного нового колбэка не потребовалось.

## Предметы

| Предмет           | id               | Профильный стат                | tags                          | База (common) | По редкости (common/uncommon/rare/epic/legendary) | Статус              |
|-------------------|------------------|--------------------------------|-------------------------------|---------------|----------------------------------------------------|---------------------|
| Пиявочная бусина  | `leech_bead`     | шанс лечения за удар (флэт HP)  | `accessory,lifesteal,on_hit`  | 20% шанс, +1 HP | 20% / 30% / 40% / 50% / 50%                       | легаси, ребаланс (вероятностный прок) |
| Амулет грифа | `vulture_amulet` | % макс. HP убитого врага        | `accessory,on_kill,lifesteal` | хил 20% HP    | 20% / 30% / 40% / 50% / 50%                         | легаси, ребаланс    |
| Амулет барьера    | `barrier_amulet` | `invulnHitsGrant`               | `accessory,invuln`            | 1 неуязвимый удар | 1 / 2 / 3 / 4 / 5 ударов                        | новый, в коде       |
| Оберег на волоске | `thread_charm`   | `healPercent` (порог фикс. 30%) | `accessory,last_stand`        | хил 25% HP    | 25% / 40% / 55% / 70% / 70%                         | новый, в коде       |

`thread_charm`/`vulture_amulet`/`leech_bead` — линейная прогрессия (+10/+15 п.п. за тир), не экспоненциальная:
подобрана вручную под процентную семантику (экспонента дала бы слишком резкий разброс между тирами);
`legendary` у всех троих не крафтится — повторяет значение `epic` (`HEAL_PERCENT`/`PROC_CHANCE` в
соответствующих `behavior.ts`), как `desperate_plate.REDUCTION`. `barrier_amulet` — особый случай: профильный
стат целочисленный (число ударов), а не процент, поэтому вместо `scaleByRarity`/линейной кривой используется
плоская таблица `1/2/3/4/5` — по одному удару за тир редкости, включая отдельное значение для `legendary` (не
повторяет `epic`, в отличие от остальных предметов слота). `vulture_amulet` перешёл с фикс. числа на % от
`maxHp` убитого врага (был плоским — не масштабировался под жирных мобов/боссов, теперь пропорционален их HP);
`leech_bead` перешёл с капирования лечения по величине урона (`scaleByRarity(1, rarity, 1.5)`) на вероятностный
прок фиксированной величины (+1 HP), тот же паттерн `ctx.rng() >= CHANCE[ctx.rarity]`, что у
`heavy_gloves`/`buckler`/`heavy_shield`. Все наборы чисел **не проверены Monte-Carlo** — прогнать
`npm run balance`, когда появятся репрезентативные билды.

## Реализовано в коде (2026-07-26, замена барьера на неуязвимость)

другая семантика мутируемого поля. Изменения:

- Тег `barrier` заменён на `invuln` в реестре тегов `content.items.md` (сам тег в `tags:` предмета сменился —
  по R8 запись реестра обязана следовать за ним).

  absorbed`) — полное гашение удара при наличии заряда (`hero.invulnHits--; dmg = 0`), без раннего `return`,
  чтобы не сломать безусловную проверку аварийного хила ниже по функции.

  HP-бара) + счётчик оставшихся ударов слева от бара (`heroInvulnText`); оба скрыты при `invulnHits <= 0`.

## Открытые вопросы

1. **Числа не Monte-Carlo-проверены** (см. «Предметы») — прогнать `npm run balance`, когда появится
   репрезентативный билд с амулетом. Числа неуязвимости (1-5 ударов) — новая шкала, старые Monte-Carlo прогоны
   зон с `barrier_amulet` (`armor-dump`/`beast-lair` rare-full, см. `roadmap.balance.md`) устарели.
2. **Хот-свап неуязвимости посреди боя** — см. «Открытые вопросы неуязвимости» №1.
3. ~~Дом предметов `amulet` в лут-таблицах~~ — **снято (2026-07, R11).** Конкретная зона-источник для каждого
   предмета этим доком больше не отслеживается, см. `src/zones/*/config.json`. Слот `amulet` формально
   внефракционен (не участвует в R10 как «чемпион одной фракции»).
4. **Судьба легаси-пары.** `leech_bead`/`vulture_amulet` остаются наступательными по триггеру. `leech_bead`
   переведён (2026-07) с гарантированного лечения (капированного величиной удара) на вероятностный прок фикс.
   величины — снимает жалобу на «слишком сильно на common», где эффект срабатывал на каждом ударе. `vulture_amulet`
   пока не тронут — числа в коде (`HEAL_PERCENT: 10/15/20/25/25%`) расходятся с таблицей выше
   (`20/30/40/50%`), актуализировать отдельно.
